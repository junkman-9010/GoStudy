# 🔍 심화 기술 분석 (Technical Deep Dive): Go Pointer Manipulation & Tracing

Go의 포인터는 단순히 데이터의 주소를 가리키는 것을 넘어, **메모리 상의 데이터 흐름을 제어하고 추적**할 수 있는 강력한 도구입니다. 본 분석에서는 포인터를 활용하여 변수의 주소 불변성, 함수를 통한 원본 수정, 그리고 다중 간접 참조의 메커즘을 심도 있게 다룹니다.

### 1. 메모리 주소의 불변성과 값의 가변성 (Value Trace)

포인터를 통해 변수를 조작할 때 가장 중요한 원리는 **"주소는 고정되어 있고, 그 주소가 가리키는 내용물만 바뀐다"**는 점입니다.

* **실험 내용**: 변수 `A`의 주소(`&A`)를 먼저 출력한 후, 포인터(`*ptr`)를 통해 값을 변경하고 다시 주소와 값을 출력합니다.
* **결과 분석**: 출력된 메모리 주소값은 동일하게 유지되지만, 해당 주소에 저장된 Value는 변경됩니다. 이는 포인터가 '데이터 자체'가 아닌 '데이터의 위치'를 다루고 있음을 증명합니다.

### 2. Pass-by-Pointer: 함수를 통한 외부 상태의 영구적 변경

Go는 기본적으로 **값에 의한 전달(Pass-by-Value)** 방식을 사용합니다. 즉, 함수에 변수를 전달하면 값이 복사되어 전달되므로, 함수 내부에서 아무리 값을 바꿔도 원본(Caller의 변수)은 변하지 않습니다.

* **해결책**: 함수 매개변수 타입을 `*int`와 같이 포인터 타입으로 정의하여 **주소**를 전달합니다.
* **메커니즘**:
    1. 함수 호출 시 원본 변수의 주소가 전달됨.
    2. 함수 내부에서 역참조(`*n`)를 통해 해당 주소의 실제 메모리 셀에 접근.
    3. 해당 셀의 값을 수정함으로써, 함수 호출이 종료된 후에도 `main` 함수에 있는 원본 변수의 상태가 영구적으로 변경됨.

### 3. 다중 간접 참조 (Pointer to Pointer: `**int`)

포인터 변수 또한 메모리 어딘가에 저장된 변수이므로, 그 포인터의 주소 또한 추출할 수 있습니다. 이를 통해 **"포인터가 가리키는 대상을 바꾸는"** 고도의 조작이 가능합니다.

* **실험 내용**: `ptr1`이 `z`를 가리키고 있을 때, `ptrPtr`를 통해 `ptr1`이 `w`를 가리키도록 대상 주소를 교체합니다.
* **기술적 의의**: 이는 리스트나 트리와 같은 복잡한 자료구조(Linked List, Tree)에서 노드의 연결 관계를 동적으로 변경할 때 사용하는 핵심 원리입니다 `(Pointer Swapping)`.

### 4. 데이터 시각화: 메모리 맵핑 (Memory Mapping Visualization)

포인터 연산을 `[Address] -> [Value]` 형식으로 로깅함으로써, 추상적인 메모리 주소와 실제 데이터 사이의 상관관계를 시각화할 수 있습니다. 이는 디버깅 시 데이터 오염(Memory Corruption)이나 잘못된 참조를 추적하는 데 결정적인 도움을 줍니다.
