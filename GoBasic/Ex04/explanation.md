# 🔍 심화 기술 분석 (Technical Deep Dive): Go Variable Declarations & Scopes

### 1. `var` vs `:=` (단축 선언)의 차이점

Go 언어에는 변수를 선언하는 두 가지 주요 방식이 있으며, 각각의 사용 용도가 명확히 구분됩니다.

| 특징 | `var` 키워드 사용 | 단축 변수 선언 (`:=`) |
| :--- | :--- | :--- |
| **사용 가능 범위** | 패키지 레벨(전역) & 함수 내부(로컬) | **함수 내부(로컬)에서만 가능** |
| **타입 지정** | 명시적 지정 또는 타입 추론 가능 | **타입 추론(Type Inference) 필수** |
| **초기화 여부** | 초기화 생략 시 **제로 값** 할당 | 선언과 동시에 반드시 초기화 필요 |
| **가독성** | 복잡한 타입이나 전역 변수에 적합 | 로컬 변수의 간결한 코드를 위해 권장 |

### 2. 제로 값 (Zero Value)의 중요성
Go 언어의 가장 큰 특징 중로 하나는 **안전성**입니다. 변수를 선언하고 초기화하지 않더라도, Go 컴파일러는 해당 타입의 **제로 값**으로 자동 초기화합니다. 이는 메모리 내의 쓰레기 값(Garbage Value)으로 인한 예기치 않은 동작을 방지합니다.

- `int`, `float64`: `0`
- `string`: `""` (빈 문자열)
- `bool`: `false`
- `pointer`, `slice`, `map`, `interface`, `channel`: `nil`

### 	3. 변수의 범위 (Scope)와 생명 주기
변수의 유효 범위는 선언된 위치에 따라 결정됩니다.

- **Package Level Scope**: 함수 외부(`package` 바로 아래)에서 선언된 변수는 해당 패키지 내의 모든 함수에서 접근 가능합니다. (전역 변수 역할)
- **Block/Local Scope**: 함수 내부 또는 `{ }` 블록 내부에서 선언된 변수는 해당 블록 내에서만 유효합니다. 블록을 벗어나면 해당 변수는 스택에서 해제되거나 가비지 컬렉션의 대상이 됩니다.

### 💡 개발 팁
- **가급적 `:=`를 사용하세요**: 함수 내부에서는 코드의 간결함을 위해 단축 선언을 사용하는 것이 Go의 관례(Idiomatic Go)입니다.
- **명시성이 필요할 때 `var`를 사용하세요**: 변수의 타입이 복잡하거나, 선언과 초기화 사이의 간격이 커서 의도를 명확히 전달해야 할 때, 또는 패키지 레벨의 변수가 필요할 때 `var`를 사용합니다.
