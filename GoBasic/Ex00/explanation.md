# Deep Dive: Go SDK 및 환경 변수 분석

이 챕터에서는 Go 프로그램을 작성하고 실행하기 위해 반드시 필요한 **Go SDK(Software Development Kit)**의 구성 요소와 **환경 변수**의 역할을 심층적으로 분석합니다.

## 1. Go SDK의 핵심 구성 요소

Go SDK는 단순히 컴파일러만 포함하는 것이 아니라, 코드를 작성하고, 빌드하고, 테스트하고, 실행하는 데 필요한 모든 도구 모음을 의미합니다.

*   **Compiler (go build)**: 작성한 `.go` 소스 코드를 컴퓨터가 이해할 수 있는 기계어(바이너리)로 변약합니다.
*   **Standard Library**: 네트워크, 입출력(I/O), 암호화, JSON 처리 등 프로그래밍에 필수적인 기능들을 미리 구현해 놓은 패키지 집합입니다.
*   **Toolchain**: `go run`, `go test`, `go mod`, `go fmt` 등 개발 라이프사이클 전반을 관리하는 명령어 모음입니다.

## 2. 핵심 환경 변수 상세 분석

환경 변수는 운영체제가 특정 프로그램이 어떻게 동작해야 하는지 알려주는 '지침서'와 같습니다.

### A. `GOROOT`
*   **역할**: Go SDK(컴파일러, 표준 라이브러리, 도구)가 **설치된 물리적 위치**를 가리킵니다.
*   **중요성**: Go 컴파일러가 표준 라이브러리 패키지들을 어디서 찾아야 할지 결정하는 기준점이 됩니다.
*   **주의사항**: 사용자가 직접 수정할 일이 거의 없으며, 보통 Go 설치 프로그램에 의해 자동으로 설정됩니다.

### B. `GOPATH`
*   **역할**: Go의 **작업 공간(Workspace)**입니다. 외부 패키지를 다운로드(go get)하거나, 사용자가 직접 만든 프로젝트 소스를 관리하는 공간입니다.
*   **구조**: 기본적으로 `src`(소스), `pkg`(컴파일된 패키지), `bin`(실행 파일) 디렉토리로 구성됩니다.
*   **변화**: Go 1.11 이후 **Go Modules (`go.mod`)** 시스템이 도입되면서, 프로젝트 소스를 반드시 `GOPATH/src` 아래에 둘 필요가 없어졌습니다. 하지만 외부 라이브러리가 캐싱되는 공간으로서의 역할은 여전히 중요합니다.

### C. `PATH`
*   **역할**: 터미널이나 명령 프롬프트에서 명령어를 입력했을 때, 운영체제가 해당 **실행 파일을 찾을 디렉토리 목록**입니다.
*   **설정 이유**: `PATH`에 Go의 바이너리 디렉토리(예: `/usr/local/go/bin` 또는 `$GOPATH/bin`)가 포함되어 있어야만, 어느 디렉토리에서든 `go` 명령어를 바로 호출할 수 있습니다.

## 3. 환경 검증 시 유의사항

`example.go` 실행 결과에서 `GOROOT`나 `GOPATH`가 `(설정되지 않음)`으로 나타날 수 있습니다. 이는 다음과 같은 상황을 의미합니다.

1.  **기본값 사용**: Go 컴파일러가 자체적인 기본값(Default)을 사용하고 있어 명시적인 환경 변수가 필요 없는 상태.
2.  **모듈 모드 활성화**: `go.mod` 파일을 사용하여 프로젝트를 관리하고 있다면, `GOPATH`에 의존하지 않고 독립적인 환경에서 작동합니다.

**결론적으로, `go version`이 정상적으로 출력되고 `go run`이 코드를 실행할 수 있다면, 기본적인 개발 환경은 구축된 것으로 판단할 수 있습니다.**
